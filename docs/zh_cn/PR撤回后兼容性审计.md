## 发布目录约定

维护者提出把默认录制放入 `agent/recordings` 符合现有协议。该目录只能存放发布模板。
用户录制、编辑后的文件及 `.bindings.json`、`.defaults.json` 继续位于根目录 `recordings/`；更新器整体替换 `agent/`，不得把用户数据移动进去。
八个模板不是八个任务的通用答案，不能自动把所有未绑定任务都绑到同一份战斗脚本。

完整前端升级与三目录资源更新是两种发布能力。旧更新器不能凭空获得替换前端的能力；必须给首次升级提供明确路径，禁止生成能被旧更新器部分安装的混合包。

## 验证计划与边界

1. 在隔离目录生成并解压实际发布包，检查模板、前端及依赖，而不是直接运行源码目录。
2. 从旧配置升级，检查脚本内容、已有绑定、重复次数、勾选状态和其他用户文件保持完整。
3. 注入损坏默认脚本、进程 EOF、升级中断/替换失败，检查隔离、报错与回滚。
4. 运行相关 Python 回归、C# 策略与界面测试，构建前端；补充打包与升级回归到 CI。
5. 不以单次游戏成功证明所有角色、恢复场景或真实鼠标性能均正常；未验证部分明确列出。

## 排除与保留

- 当前宿主 `AppPaths.DataRoot` 与安装目录相同，尚无数据根目录分离导致恢复状态路径错误的证据。
- 原有冒险任务也存在 `assets/data` 数据依赖，应按现有发布结构保留；不能把旧问题误记为这次录制迁移引入。
- `.defaults.json`、`.bindings.json` 损坏应有明确错误及恢复入口，不能静默覆盖用户绑定。
- PR 继续保持关闭；本轮修复不代表可以直接重新提交。

## 修复与验证结果

### 已实施

- **A1**：将八份发布模板和清单迁至 `agent/recordings`，同步加载器、预览、任务安装器和测试。用户根目录 `recordings/` 不迁入 Agent，不覆盖其内容。
- **A3**：新增纯迁移规划模块并接入现有任务同步备份事务。明确的旧文件选择转为绑定；`@latest` 固定为迁移时已有的最新用户文件；已有绑定优先。不同实例对同一任务选择不同脚本时，在写入前拒绝自动合并。绑定写入失败会回滚任务及实例配置。迁移实现随 `agent/task_asset_sync.py` 发布，支持没有 `assets/` 的客户端目录，源码的 `tools/sync_task_assets.py` 复用同一实现。自动更新协议保持原样，完整客户端手动升级时执行迁移。
- **A4**：已有明确文件引用的自定义任务不再强制要求新增绑定。新任务使用 `@task:` 时仍须用户选择合适脚本；未绑定时在执行前提示，这是必要配置条件。没有向公共包写入个人绑定，也没有把八份模板任意分配给不同副本。
- **A5**：坏 JSON、非对象 JSON、异常编辑元数据的同名用户文件保留原样；模板另取不冲突名称。损坏的默认登记索引不再使整个服务退出，界面展示诊断，已有用户文件仍可列出，无关原生任务可以继续。没有自动重置损坏索引。
- **A6**：任务发现和资源安装复用同一个链接解析函数，支持带前缀、对象格式和声明的锚点链接。补上跨文件依赖复制；脚本库合并实例能力，执行时使用正在运行实例传入的真实覆盖参数，避免取到其他实例的配置。
- **A7**：EOF、断管、损坏响应和进程退出统一标记断线；不再悄悄重建空会话。录制互斥会释放，业务校验错误仍保留会话。通过真实子进程故障注入验证。
- 补充修复旧版字符串形式的 `custom_action_param`：Pipeline v1/v2 的文件名字符串和 JSON 对象字符串均按回放器的规则解析，避免任务目录在 `.get()` 处异常。
- 实际压缩包验证另发现：默认入库会不必要地重写已经存在的绑定索引格式。现已改为只有新增默认绑定时才写入，验证原有个人绑定文件保持逐字节一致。

### 已确定的发布与升级路径

现有 `updater.py` 仅替换 `resource`、`agent`、`interface.json`，也不会安装包里的新版 `updater.py`。因此不能通过“给 ZIP 多加几个前端文件”完成首次升级。

本次按项目协作安排保留三目录资源更新协议，用户重新下载完整客户端并手动更新前端。完整客户端由定制前端构建产物、项目资源和运行依赖组成，CI 提供经过文件范围限制的前端附件；不夹带预览库或个人配置。根目录 `version.json` 保持已发布 2.2 的真实清单，发布者需要根据最终产物生成新清单。

现有宿主默认隐藏通用前端更新按钮，但内部更新方法仍指向 MFAAvalonia 官方渠道。现已增加调用级保护，并在软件版本旁复用原命令提供“前端升级说明”，避免之后误用通用包覆盖工作台。资源更新入口保持原样。

完整手动升级步骤见 `docs/zh_cn/脚本工具-使用说明.md`：退出并备份旧助手，先从新版目录运行迁移工具，保留旧配置和脚本，再覆盖新版程序。`--update-version` 只同步资源版本字段，不覆盖用户控制器定义。已有新绑定保留；没有可迁移录制的任务明确要求首次绑定。

PR #1 保持关闭，本轮修复单独整理新的 PR。三目录资源更新已验证其职责范围，不能把它描述成自动前端升级。真实鼠标偶发迟滞和自动重启所有游戏场景没有完整实测结论，本次不宣称所有可能的问题都已消除。

### CI 的 Windows 临时路径回归

PR #2 的首轮 `verify` 在 Python 步骤有 5 项故障注入测试失败。测试夹具保留了临时目录的原始路径，而迁移器和脚本服务会先解析实际路径；Windows 的 8.3 别名与完整路径指向同一目录，但 `Path` 对象的路径比较不相等。4 项写入/回滚测试未命中注入目标，因此得到空错误列表；1 项模拟目录越界测试也未命中目标，未抛出预期异常。

使用真实短路径作为子进程的 `TEMP`/`TMP`，在修改前复现了完全相同的 5 项失败。修复仅规范化两处测试根目录，补充注入命中次数断言，并新增 `tests/test_windows_temp_paths.py`，不改变生产代码的路径约束或回滚行为。修复后 Python 3.12 与 3.13 的短路径专项检查通过，普通环境及完整短路径环境的 243 项回归通过（本地 7 项按条件跳过）。
