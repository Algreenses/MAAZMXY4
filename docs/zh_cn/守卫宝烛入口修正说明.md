# 守卫宝烛入口修正与验证记录

> 2026-10-27 后续真实画面检查：通过实际下载的测试版捕获普通地图、任务面板、副本和设置菜单画面。正确悬赏及场内识别均命中，守卫太宗未误命中宝烛任务；人工进关和返回地图成功。设置菜单打开时场景模板仍可命中，因此增加了回放前的菜单阻断，并用真实抓取的菜单和正常战斗画面分别验证命中与放行。尚未使用真实个人录制完成自动单轮回放。

> 随后的真实画面串联测试发现：拦截弹窗的全屏 OCR 会缓存识别结果，倾斜的“已接受”标记可能被漏检，导致四个悬赏任务在已接取时仍无法进关。现保留原识别，并增加针对标记区域的独立文字识别；任务详情名称、已接取状态和“前往副本”按钮仍需同时匹配。使用真实捕获画面和本机录制副本完成的加速内存回放已验证事件分派和返回分流，不代表真实战斗完成。

## 原因与范围

旧 Pipeline 的“定位”包含进入须弥山、从洲地图返回世界地图及打开悬赏榜的路线。返回确认和自动恢复也以旧大厅、卡片和世界地图为依据，仅替换入口会留下无法确认退关或错误报告恢复就绪的问题。

本次将守卫宝烛改为与守卫太宗相同的“任务 → 悬赏任务 → 前往副本”路线，复用现有任务图标、OCR 组合识别和场景模板。点击前同时核对任务详情中的“守卫宝烛”、已接受状态和前往按钮；错误目标不会点击。旧导航节点及不再引用的 16 份导航/大厅/旧场景模板已移除，旧截图仅在离线测试中保留。

## 连带行为

- 保留原初始化入口和 `bounty-candle` 绑定别名，更新不会要求既有用户重新绑定；重复次数仍由宿主队列控制。
- 进关后复核副本画面再回放。完整返回录制只确认返回；仅战斗录制沿用设置、返回地图流程。两次确认地图上的任务图标后才完成一轮。
- 自动恢复保留登录和已占用存档校验，只有回到能打开任务面板的地图才报告就绪。世界地图或旧悬赏榜不再被判定为恢复成功，也不会通过它们导航到须弥山。无法识别时停止并提示手动返回任务地图。
- 已有个人录制和绑定不自动改写。录制应从副本内开始；含世界地图、须弥山或悬赏榜进关动作的旧录制，需要先裁剪或重新录制。
- 任务页、脚本工具说明、素材说明及历史验收记录的适用范围已同步修正。本地 AGENTS.md 增加对应约束，不随安装包发布。

## 自动化检查

- 新入口/兼容性回归在修复前检出旧入口、返回和恢复依赖的 3 项失败，修复后通过。
- 入口、任务状态、目标防误点、任务目录、资源同步及发布兼容性共 86 项检查：85 项通过，1 项按环境跳过。
- 2 项 Maa 原生离线测试通过：52 条静态/合成像素识别断言，以及内存控制器下三次点击进关、保存编辑后再次回放、返回确认、已有存档恢复和错误世界地图停止。测试不访问真实窗口或发送真实输入。
- 当前 16 个 Pipeline 的仓库 Schema 检查通过。interface Schema 仍拒绝现有 `repeatable`、`repeat_count` 宿主扩展字段；对修复前提交核对后确认错误完全相同，本次没有增加此类错误，也未为消除错误删除任务计次字段。

## 当前验证边界

真实游戏中的入口和返回已由人工操作核对；真实抓取画面驱动的脚本测试使用内存控制器与加速计时，未向游戏发送回放输入。真实游戏中从开始任务到录制回放、战斗和返回的自动单轮仍需单独验收。具体版本、下载安装与测试结论以对应发布记录为准。
