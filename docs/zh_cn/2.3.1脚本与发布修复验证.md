# 2.3.1 脚本改名与发布资源修复

基线：上游 `v2.3.1` / `9f76fa26da7944e001c45836467e55d095175280`。修复分支资源版本为 2.3.2；本文记录本地隔离验证，不代表已经发布或远端 CI 通过。

后续更正：下文提及的旧包包含 7 份来自原工程的个人录制作为默认模板，原文“不含用户录制”仅指未收集客户端根目录的用户数据，并不表示旧包未包含这些个人模板。当前发布清单仅保留格式示例，也不再默认绑定任务；下文的数量和结果为当时的历史记录。

## 确认的根因

1. 脚本库缺少已保存文件的改名入口。原 `rename` 服务只修改编辑文档的 JSON `name`，用于首次保存和另存为；文件列表也读取该字段。因此仅在资源管理器改名不会改变显示名称，而且 `.bindings.json` 仍指向旧文件。
2. [官方 2.3.1 整包](https://github.com/Inkyu-Zero/MAAZMXY4/releases/tag/v2.3.1)中的任务资源与同一版本源码不一致。下载的 `MAAZMXY4.v2.3.1.exe` SHA-256 为 `cf59d9470dd71cb2f0a4ad21cddcede25b55ca3fafde6d653f6475fdcf22a351`，与 GitHub Release 公布值一致。仅解压检查，没有执行其自解压程序。
3. 包内钟晷极地等 10 个普通刷关任务缺少 `script_binding.recorded_return_next` 和对应的返回确认节点，旧回放参数仍为 `示例-最小`；包内任务选项仍有旧“回放文件”。源码中已经具备这些返回路线。绑定脚本后选择“包含返回地图”会在 `TaskScriptPlan.Prepare` 中被正确拦截，尚未进关，与战败识别素材无关。
4. 本轮首个 2.3.2 候选完整 ZIP 漏收集官方 `MAA造梦西游4.exe` 启动器。直接运行 `MFAAvalonia.exe` 和包内 Python 服务成功，未覆盖标准入口“启动器 → `pythonw.exe` → `updater.py` → MFA 前端”，因此先前整包检查不能证明标准入口可用。
5. 官方旧更新器替换三项资源时会保留用户录制和配置的原始字节，但不会将旧“回放文件”选择转换为新绑定。已有隔离复现表明：录制文件仍在，更新后仍可能因未绑定正常停止。手动迁移必须在替换旧 `interface.json` 前进行。
6. `tools/setup_runtime.py` 曾裁掉 `tkinter` 且未复制 Tcl 数据、`pynput` 和 `six`。按该工具重建的运行时即使能运行 Maa Agent，仍可能无法启动外部更新器或开始录制。本轮修正复制范围，并让运行时自检与完整包共用必需依赖清单。

## 改动

- 工具栏和脚本行菜单提供“重命名…”。复用文件库锁、修订校验、原子发布，同步 JSON 名称、文件名、任务绑定、默认登记和当前选择；故障回滚，不覆盖重名文件或并发创建的文件。当前文档跟随新路径，后续保存不会重新创建旧文件。
- `tools/build_release.py --client` 复用 `build_update.collect` 统一取规范资源，合并通过 `--launcher` 指定的官方启动器、明确指定的前端、完整 Python 和依赖安装 BAT。不会打包预览目录中的个人录制、配置和日志。
- `--verify-client` 检查解压结果的启动器、必需依赖、公共任务、选项和所有普通刷关返回确认，能拒绝漏启动器或上述官方旧资源组合。未声明路线的自定义任务仍会停止，并提示更新资源或配置路线，不会跳过确认伪报成功。
- 保留 v2.3.1 依赖安装脚本，校验 CRLF、首次 `/install` 参数和打包内容；保持三项目资源更新协议和手动前端升级方式。根目录 `version.json` 仍描述真实已发布资源，未写入虚构的新版本地址或哈希。

启动器取自上述已校验的官方 v2.3.1 发布包，`MAA造梦西游4.exe` 的固定 SHA-256 为 `a0367870662916dc6abcaadf76b8321e3979a82b7c894d9d2004e3eb90197e46`。标准入口保留原官方启动链路，不新增更新协议。

## 更新入口与发布边界

### 补齐启动器后的 2.3.2 完整包

最终本地候选文件为 `MAAZMXY4-v2.3.2-win-x64.zip`，181,908,621 字节，SHA-256 为 `5962bbd7a1bb30e018e32770e5a54dc0d73b5b4a1270ee74d4065ede9147ef36`。尚未发布到 GitHub。

- 解压后 `--verify-client` 通过：3,743 个发布文件，标准启动器、前端、Python/Tk、8 份默认录制以及 10 个任务的返回确认齐备；包内不含用户录制、配置、绑定、日志、pip、缓存或临时 wheel。
- 包内 Python 3.12.13 可导入更新器、Tk、录制依赖和 Maa；Python 包与前端实际原生库均为 Maa v5.12.3，16 个原生 DLL 哈希一致。`.deps.json` 中的包装依赖版本不能替代实际 `MaaVersion()`。
- 官方启动器在中文、空格路径和外部工作目录下的安全替身链路通过，真实更新器能使用 `MFAAvalonia.exe` fallback。另从实际解压包的标准入口启动真实前端，标题显示项目 2.3.2；更新日志记录远程 2.2.1、本地 2.3.2，并成功启动前端。仅空队列启动检查，没有执行游戏任务；首次启动的默认窗口搜索与空队列连接日志不能当作关卡验收。
- 官方启动器及编译前端的全部 10 帧图标与本项目 `新图标.ico` 相同。
- 本地安装补齐标准启动器，3,742 个程序/资源文件与该 ZIP 的哈希一致；`interface.json` 保留现有 4 项额外选项，公共任务、选项和项目版本分别校验。18 个用户脚本、绑定和配置文件的哈希未变，安装前备份保存在客户端 `backup/`。
- 本轮发布与运行时依赖回归 8 项通过，包含拒绝缺失/非官方启动器、缺 Tk/Python、目录伪装关键文件，以及重建运行时保留更新器和录制依赖。用户真实录制、关卡及恢复测试仍待手动确认；fork 发布和下载包全流程验证仍按下列门槛执行。

`updater.py` 与 MFA 宿主内建更新是不同链路。前者由官方启动器调用，按远程 `version.json` 下载，只替换 `resource/`、`agent/` 和 `interface.json`；不能安装前端，也不执行旧选项到任务绑定的迁移。后者通过 GitHub Release 选择资产，在包内发现核心程序文件后会尝试安装程序文件；完整 `win-x64` ZIP 可能被选中。保护通用 MFA 软件更新的补丁没有禁用这条内建资源更新链路，尚未完成的内建升级验证不能写成已通过。

当前公共配置的 GitHub 地址、外部更新器版本源及 `tools/build_update.py` 的默认 Release 仓库仍指向原仓库。fork 发布清单必须核实实际下载仓库、资产 URL、体积及 SHA-256，不能直接沿用生成清单中的上游地址；fork 试发布不更新上游或共享 R2 清单。

本轮后续顺序与门槛如下；在取得对应证据前均按待完成记录：

1. 补齐启动器后重建最终完整 ZIP，解压核对标准入口、依赖、规范资源和哈希；完成本地安装并比较受保护用户数据，交给用户手测。
2. 用户确认手测通过后，推送并在 fork `Algreenses/MAAZMXY4` 发布完整 2.3.2，记录发布提交和实际资产哈希。
3. 重新下载该 Release 的实际安装包，在独立工作区检查全新安装、官方 2.3.1 手动迁移、标准启动器、脚本与绑定、单轮任务以及失败恢复；内存控制器和模拟数据不能代替真实游戏结论。内建资源更新另行核实，不以三项更新器测试代替。
4. 下载包验证通过后，再整理上游 PR，分别填写本地检查、用户手测、安装结果和准确提交的远端 CI；未执行的检查明确保留边界。

## 复现和发布前检查

```powershell
python -X utf8 -m unittest discover -s tests -p "test_*.py"
dotnet run --project frontend/tests/NativeRecovery/NativeRecovery.csproj -c Release
dotnet run --project frontend/tests/StudioPage/StudioPage.csproj -c Release
./tools/build_frontend.ps1
python tools/build_release.py --client --launcher "<官方解压目录>/MAA造梦西游4.exe" --frontend "<编译输出目录>" --python-runtime "<完整内嵌Python目录>"
python tools/build_release.py --verify-client <完整包解压目录>
python tools/build_update.py --version 2.3.2
```

发布完整客户端后用户才能获得新增改名按钮。外部 `updater.py` 的三项资源更新可修正返回流程和 Agent，不能替换 EXE/DLL，也不能代替完整手动迁移。打包前不要压缩已经运行过的个人目录；完整升级步骤见[使用说明](脚本工具-使用说明.md#手动升级客户端)。
