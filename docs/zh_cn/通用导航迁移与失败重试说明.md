# 通用导航迁移与失败重试

本次工作从上游 `main` 的 `363d8dc` 建立 `feat/native-navigation-retry`，目前已同步至上游 2.3.7 的 `4061dcc`。在此基础上，普通关卡场景确认超时改为安全停止，移除包括烛时在内的“点击场外”坐标回退，避免加载延迟或高亮识别差异导致误入其他关卡。沿用现有 MaaFramework Pipeline、任务队列、控制器、脚本库和前端选项编辑器，没有迁入旧工程的 Qt 界面、应用调度器、运行环境、个人录制或绑定。

本分支资源版本为 **2.3.8**。源码提交与客户端正式发布分别验证；正式 `version.json` 仍描述已发布的上游产物，不提前写入尚不存在的下载地址。统一客户端与资源更新的分发规则见[更新协议与发布规范](更新协议与发布规范.md)。

旧库的 621 份裁剪素材及 34 个源界面、74 条源候选边保留来源记录。目前基础图编译出 34 个定位界面、74 条候选边，其中包含新增的日常菜单暂停恢复边；缺少当前素材的商店入口仍未启用。图再由任务注入具体入口，这些数量不代表所有路径已经实机验收。

采用新工程已有的“任务”图标代替旧工程须弥山大厅的本机校准条件。旧悬赏榜可以被识别和关闭，但运行图没有进入悬赏榜的边；悬赏任务只用“任务 → 悬赏任务 → 本任务详情 → 前往副本”。地图 A/B 是源库中的校准标识，并未未经确认给其添加地名。

日常菜单现在使用两个已知控件联合识别，暂停使用当前及源库两种文案；确认菜单和暂停提示后才恢复。世界图的须弥山入口依据官方具名图片确认语义，实际点击仍匹配本项目当前客户区的佛像素材与独立世界图地标，不使用攻略中的固定坐标。神秘商店仍缺少可靠的当前入口，暂不启用；登录及存档继续沿用宿主已有、默认关闭的显式恢复配置。

## 当前完整度：2.3.8 候选

系统已经具备共享的定位、规划和原生执行框架，但距离“从任意界面自动进入任意任务”还有缺口。素材入库、图上可达、静态画面识别和实机成功是四种不同证据，不能相互代替。

| 范围 | 已有能力 | 当前限制 |
| --- | --- | --- |
| 通用定位与规划 | 621 份旧裁剪素材；基础图 34 个界面、74 条候选边；同帧消歧、动作后重定位、有界重试 | 素材数不等于可执行任务数，大部分一般面板路径尚未实机逐条验收 |
| 四个悬赏任务 | 注入后每个图 40 个状态、84 条边；地图、任务面板和已接详情可接入入口，能规划已知面板返回、日常菜单收起及已确认世界图回到任务地图 | 需事先手动接取；不自动接悬赏，也不支持任意列表滚动或未知弹窗 |
| 七个普通关卡 | 已补已知面板关闭、任务面板关闭、暂停恢复到本关入口的路径，继续复用原来的入场、回放、结果与重试 | 必须最终看到本关图标；未标定跨洲选择和地图拖动。错误地图不会通过乱开面板、世界地图绕路尝试 |
| 挑战成功与失败 | 使用提供的真实结算素材；失败先释放输入、返回并确认，再按开关重试；失败尝试不占额外完成次数 | 实时结算时序、其它角色/画面版本和实际死亡仍需手测；正常刷经验退关不要求悬赏变成 1/1 |
| 异常与恢复 | 未知画面、歧义、验证码、取消和预算耗尽会停止；已确认的任务地图有暂停恢复分支 | 这些停止条件不等于有自动解决能力；不新增任意账号登录、存档选择或通用重启流程 |
| 分发与框架适配 | 运行依赖都在现有 `agent/`、`resource/` 范围，使用当前 Context 和原生 Pipeline | 候选资源包需要已有完整客户端；不包含前端、Python 或安装器 |

2026-10-28 的离线可达性检查显示：四个悬赏图均有 37 个状态可规划到目标，另外 3 个不可达状态为开始游戏、存档记录和生存大冒险答题。这仅验证图上的路径存在，不代表 37 个界面已经实机通过。普通关卡的关闭面板路径现在有到目标的候选连接，关闭后必须重新识别本关图标；只回到某个地图不能判为导航成功。普通地图未出现本关入口时不发送额外导航输入。

本次检查还发现并修复了 `task_graph()` 中列表共用问题：任务面板和普通关卡目标的 `obscures` 直接引用同一 `maps` 列表，补充遮挡关系时将目标加入了自身的遮挡列表，导致七个普通关卡即使在正确地图也报图无效。改为分别复制列表；`test_every_injected_task_graph_can_locate_its_map_and_target` 在修复前产生七个关卡错误，修复后覆盖全部十一项任务的地图、目标和普通关卡面板消歧。此前仅验证基础图及悬赏流程的检查没有覆盖这一动态注入问题。

普通关卡连接通过复用现有关闭边补齐，不增加第二套输入执行器。原生内存控制器在真实背包、任务详情和关卡地图像素上验证了关闭后找到朱电入口；暂停地图用例是明确标记的合成夹具。全图定位耗时及其对真实预览/输入的影响尚未实测，反向 RPC 和内存控制器检查不能替代该性能验收。

## 网上与论坛素材审阅

来源与采用/拒绝原因记录于 `agent/data/navigation/research.json`。完整网页图片只保存在本机审阅缓存，不将论坛个人信息、攻略水印或整张历史截图加入客户端。

- [4399 须弥山入口图](https://m.news.4399.com/gonglue/zmxy4/wenda/558932.html)明确标出了佛像岛名称，支持将现有佛像素材用作世界返回入口，点击前仍需同时匹配世界图地标。
- [4399 西牛贺洲图](https://m.news.4399.com/gonglue/zmxy4/wenda/702656.html)和[北俱芦洲说明](https://news.4399.com/gonglue/zmxy4/wenda/605453.html)较旧，地图岛屿数量、解锁状态与当前不同，仅作参考，不据此启用跨洲任务点击。
- [4399 早期商店攻略](https://news.4399.com/gonglue/zmxy4/wenda/516323.html)是 NPC 对话框，与当前顶部图标和标签式商店不一致，未采用为运行模板。
- 电脑页游论坛的[日常菜单公告](https://bbs.4399.cn/thread-view-tid-48456050)与[2026 冒险活动公告](https://bbs.4399.cn/thread-view-tid-51889859)用于核对功能层级。[地图位置调整公告](https://bbs.4399.cn/thread-view-tid-48602648)也说明旧图坐标不能当成当前坐标。手游论坛结果已排除；跳转登录的旧论坛未登录或读取私有内容。

仍需后续采集的重点是当前版本的具名洲入口、幽冥血海左右拖动、六欲魔天、当前商店入口及更多角色的结算/遮挡负例。自动登录、任意存档选择和未确认的答题页退出仍未开放。

同一轮定位只使用一帧。只有声明的遮挡关系可解决同时命中；未知、歧义或阻断提示会停止。每条边最多尝试两次，受步数、时间和节点超时约束。重试同一边与失败轮次重试是两种预算，不会通过刷取计数节点补偿导航失败。

已知任务地图的失焦暂停沿用新工程现有模板恢复：同帧确认暂停文字与任务图标后点击暂停提示，再重新定位。该分支不能仅凭“继续游戏”几个文字对未知页面执行点击。

开发导入入口为 `tools/import_navigation_library.py`；只有此离线工具需要 Pillow。原始截图先统一到短边 720，再重新裁剪，保留源哈希及结果哈希。`tools/navigation_privacy_masks.json` 对已审阅的昵称、公告中的联系号码及存档时间等区域作遮挡，源截图变化时要求重新审阅；运行定位探针不得包含这些遮挡区域。全图夹具与一般素材保留遮挡标记，不能将它们当作新抓取的实机证据。

## 单轮与失败次数

```text
准备并固定脚本修订 → 定位/导航 → 校验场内 → 回放并观察结算
                                             ├─ 挑战失败 → 释放输入 → 返回地图并确认
                                             │                         ├─ 重试关闭/用尽：停止，不计次
                                             │                         └─ 重试启用：回到本轮导航
                                             └─ 成功结算/原有退关 → 确认返回 → 本轮成功 → 下一轮
```

普通关卡保留 Maa 的刷取配额；守卫宝烛继续由宿主重复次数控制，不叠加内部成功循环。失败后的导航跳过刷取计数入口，因此重试不消耗另一轮配额。每轮默认最多失败重试三次，可配置 1～20，默认关闭。

`agent/battle_outcomes.py` 在克隆的当前 Context 中串行采样，只做截图和识别；回放线程拥有输入和分支变更。录制鼠标点击前再检查当前结算，避免录制的返回动作提前关掉失败页而误计成功。输入失败、识别异常、取消和清理失败均不能转成成功或死亡自动重试。对已按下的键鼠进行释放后，才允许进入返回地图分支。

结果已被监测确认后，分支会保留该结果。如果释放原本按住的鼠标已触发返回地图，会确认当前地图并继续处理，不再强行等待已经消失的失败标题。配额原生回归包含这一持鼠标时死亡的场景。

成功与失败标题使用用户提供的两张真实素材，返回按钮还需与相应标题同帧命中。保持原有经验任务语义：未出现失败页且正常退关也可完成一轮，不把悬赏 0/1 一律视为失败。

## 避免的兼容问题

- 复用已有“脚本任务设置”，不重复声明 Maa 节点。任务同步会在写入前拒绝重复节点。
- 保持任务名称、公开入口、`task-…` 标识与 `bounty-candle` 别名，保留原有个人绑定、勾选、重复次数及选项；仅补充默认关闭的新选项。
- `get_node_data()` 的复合识别结果是 Maa 归一化格式，不能直接回灌为源 Pipeline JSON。目标识别通过原节点名称调用 `run_recognition()`，不会执行其点击动作，也不会把子 OCR 误变成 DirectHit。
- 导航边由运行时选择，不只通过静态 `next` 可达。`task_asset_sync.py` 读取资源依赖声明，和现有备份/回滚事务一起同步共享 Pipeline、运行元数据与素材。
- 构建继续使用现有 `build_update.py` / `build_release.py` 的文件范围，新增内容均位于已有 `agent/`、`resource/` 范围；不改升级协议或创建另一套前端。

## 验证与边界

常规 Python 回归覆盖原生任务预检、脚本固定修订、导航预算、失败开关/用尽、输入释放、歧义、取消、依赖同步及包文件范围。

可选原生测试：

- `NAVIGATION_NATIVE_TESTS=1`：`tests/test_navigation_native.py`。在内存控制器中识别真实成功/失败页、真实守卫太宗详情和源库多个面板，禁止真实输入。配额场景执行首次死亡后重试，再完成两轮，要求总共尝试三次、配额命中两次。该配额用例单独替换已有副本场景检测，不能证明太宗场景模板或实机入场效果。
- `CANDLE_NATIVE_TESTS=1`：`tests/test_bounty_candle_native.py`。原有场内、设置菜单、存档及退出检查，使用静态或明确标记的合成夹具。
- `MAA_AGENT_NATIVE_TESTS=1`：`tests/test_battle_outcomes_transport.py`。独立 Agent 进程经真实反向 RPC 完成后台截图和识别，控制器禁止设备输入；验证后台工作线程不会阻塞原有 Agent 通道。

以上检查不启动客户端、不连接游戏、不重启用户进程。它们不能代替不同角色、画面缩放、实时输入和真实死亡后的验收。实机测试须先取得当前范围的许可，使用隔离客户端与明确的单轮；本地正在使用的助手保持隔离。

仓库自带 schema 可验证所有 Pipeline；`interface.schema.json` 对守卫宝烛既有的宿主扩展字段 `repeatable`、`repeat_count` 报一处错误。同样的错误可在本次分支起点 `363d8dc` 的 interface 上复现。本次保留这些控制宿主重复的字段，没有为消除校验告警而删掉既有计次行为；新增选项没有增加其它 schema 错误。

## 手动验收

1. 此次完整测试客户端安装在独立的 `MAAZMXY4-install-test` 根目录，标准入口为该目录下的 `MAA造梦西游4.exe`，包含前端、Python 和当前资源；不要与早先仅有三项内容的候选资源 ZIP 混用。日常客户端保持隔离。目录准备完成不代表实际启动已经通过。
2. 手动停止其它助手对同一游戏窗口的任务后，再启动测试客户端。此次候选资源版本为 2.3.8；在任务选项中检查“任务失败后自动重试”。测试期间不要执行正式源的资源更新。最先检查标准启动器、窗口选择及真实截图，再开始单轮回放。
3. 从脚本库导入自己的副本内战斗录制并绑定守卫太宗，根据录制是否包含退关选择返回方式。初次只设一轮，失败最多重试一次。测试数据留在实验客户端，不进入发布树或默认模板。
4. 手动接好任务，可分别从任务地图和已打开的悬赏详情启动。确认点击正确的已接任务，回放后正常返回。
5. 发生真实挑战失败时，检查后续输入停止、返回地图、启用时重新进入同一任务，以及失败尝试没有占用额外完成次数。关闭重试时应返回后结束；取消任务后不应自动重开。
6. 测试普通关卡前先手动切到任务要求的地图，确认本关入口可见，再打开背包或任务面板测试自动关闭与重新核对。测试暂停后恢复；切到错误地图的负例应停止且不误入关卡。

## 分发与升级准备

本候选包含前端修复、时长编辑和无限次数参数适配，因此应手动安装完整客户端。原资源更新器仍只替换 `agent/`、`resource/`、`interface.json`，不会安装新增前端；不能用三项资源更新验收代替此次完整升级。资源更新保留根目录个人库和配置，但不保留这两个被替换目录中的私有插件或自行改过的资源。此次不改升级协议。

本地候选升为 2.3.8 是为了与已发布 2.3.7 区分；尚未修改正式发布清单。正式发布前还要完成用户实机验收、发布地址重新下载与安装验收，然后用最终文件的实际 URL、大小和 SHA-256 更新清单。客户端优先读取 R2 的有效清单，不能只改 fork 或 GitHub 后就宣称原仓库用户会收到更新。
